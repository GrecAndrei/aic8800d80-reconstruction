# harness_v26 — Hybrid Rebuild Ledger

v26 is the rebuild-control layer. It does not try to clean all Hex-Rays C at
once. It starts from a byte-faithful baseline and tracks every unique v19
function in a per-function ledger.

## Inputs

- `harness_v25/out/function_index.json` — canonical deduped function index
- `inputs/firmware/*.bin` — raw firmware bytes loaded at `0x100000`
- `harness_v19/decompiled/<image>/*.c` — advisory function-size comments

## Commands

```bash
go build -o bin/fwhybrid ./cmd/fwhybrid

bin/fwhybrid ledger  # writes harness_v26/ledger/functions.jsonl
bin/fwhybrid emit    # writes harness_v26/out/<image>/hybrid.c
bin/fwhybrid build   # compiles hybrid.c to ARM relocatable objects
bin/fwhybrid link    # links hybrid.o at 0x100 and emits hybrid.bin
bin/fwhybrid package # wraps linked code with the original 0x100-byte header
bin/fwhybrid diff    # compares packaged firmware against original bytes
bin/fwhybrid verify  # hashes ledger byte ranges against raw firmware
bin/fwhybrid queue   # ranks syntax-clean C promotion candidates
bin/fwhybrid promote # marks top queue entries as c_candidate
bin/fwhybrid check   # host syntax-checks emitted hybrid.c files
bin/fwhybrid report  # writes harness_v26/report.json

# Full deterministic run:
bin/fwhybrid all
```

## Modes

- `asm_exact`: default. Emits original raw firmware bytes as top-level asm.
- `c_candidate`: tracked as a promotion candidate, but still emitted as raw
  bytes until an equivalence gate can prove the C replacement.
- `c_verified`: reserved for future C replacements with equivalence evidence.
- `blocked`: no valid byte range or source for the function.

The first v26 milestone is an all-`asm_exact` ledger/source baseline. Later
work promotes small leaf functions to C only after compile and verification
gates pass.

## Outputs

```text
harness_v26/
├── ledger/
│   ├── functions.jsonl      # one record per image/address
│   └── manifest.json        # input and image summary
├── out/
│   ├── <image>/hybrid.c     # generated byte-faithful source
│   ├── <image>/verify.json  # byte hash verification summary
│   ├── <image>/hybrid.o     # ARM relocatable object
│   ├── <image>/hybrid.elf   # linked ELF, .text at 0x100
│   ├── <image>/hybrid.bin   # flat linked code image
│   ├── <image>/hybrid_firmware.bin # firmware-sized image with original header
│   ├── <image>/diff.json    # original-vs-rebuilt byte comparison
│   ├── build.json           # compiler/object-build status
│   ├── link.json            # linker/objcopy status
│   ├── package.json         # firmware wrapping status
│   ├── diff.json            # aggregate original-vs-rebuilt byte comparison
│   └── check.json           # host syntax-check status
├── queue/
│   ├── c_candidates.jsonl   # ranked C promotion queue
│   ├── summary.json         # queue run metadata
│   └── promote.json         # last promotion run metadata
└── report.json              # aggregate v26 state
```

`build` is toolchain-aware. If no ARM compiler is available, it writes
`build.json` with a skipped/error status instead of blocking ledger, emit,
verify, or report. The current build gate emits relocatable `hybrid.o`
objects. `link` uses a generated linker script with `.text` at `0x100` and
absolute `PROVIDE()` symbols for promoted C data references. `package`
preserves the original firmware header and pads/truncates to the original
image size.

`queue` is intentionally conservative. It only ranks byte-exact functions
with small v25 type-rewritten C, no parsed access patterns, few real callees
after parser-noise filtering, and `gcc -std=gnu89 -fsyntax-only` success.
Queue membership does not mean semantic equivalence; it means "safe to inspect
or promote next."

`promote` updates the ledger from `asm_exact` to `c_candidate` for the top
queued entries. It does not mark anything `c_verified` and does not replace
firmware bytes in the packaged image; that requires a later equivalence gate.

## Current v26 baseline

The byte-faithful rebuild path emits top-level assembler blocks, not C naked
function wrappers. This avoids compiler-inserted padding and lets the emitter
copy every original byte range, including non-function gaps and image tails.

As of the current generated artifacts, `bin/fwhybrid diff` reports all four
packaged `hybrid_firmware.bin` files as `byte_identical` to their matching
`inputs/firmware/*.bin` files. This proves the v26 packaging baseline is
structurally exact. It does not prove any C candidate is semantically
equivalent yet; `c_verified` remains the required gate for real C replacement.
