## Method

1. **v14 pipeline** (Unicorn + behaviorsynth) was already producing
   29,870 behavioral synth files in `artifacts/releases/aic8800d80-rebuild-v1/synth/`.
   Most truth lane functions were already traced, but the v13 text-based
   scorer rejected them as "missing callees" because they only had MMIO ops
   (leaf functions).

2. **Strong verifier** (`harness_v15/verifier/verify.py`) correctly accepts
   real behavioral bodies by detecting:
   - **Leaf functions** (no real callee): require real register/MMIO operations
   - **Calling functions** (has BL targets): require at least 1 callee matching
     a real BL target in r2 disasm
   - Rejects v13 behavior_lift templates (template_detected)
   - Filters out `blx rN` (register-indirect, not a nameable target)

3. **v14 pipeline address fix:** `behavioral_fingerprint.py` loads binaries
   at `BASE=0x1200000` and expects the `address` field to be `BASE + file_offset`.
   For 6 truth lane functions in fmacfw_h, the addresses in
   `extraction_out/reconstruction/truth_lane_state/truth_lane_targets.json`
   are RUNTIME (base 0x100000) rather than file offsets. Fixed by converting:
   `entry = 0x1200000 + (truth_lane_addr - 0x100000)` for fmacfw_h.

4. **Re-ran v14 pipeline** for 6 missing functions with corrected addresses.
   All 6 produced real behavioral files (7 generated total, including
   `log_system_init_mode2` which was already in the v14 release).

## What Did NOT Work (and Why)

The v15 LLM-as-decompiler approach (5-pass parallel model worker, $2.75 spent,
33M tokens) was a **diversion**. The LLM produced fictional ARM-to-C
translations, mostly stuck in tool loops, generated 7 of 13 fails with
"no_c_function_extracted". This was the wrong path.

The right path was already in the repo: v14's behavioral trace replays.
The LLM has no business translating ARM assembly to C — that is the
Unicorn emulator's job.

## What Did Work

**The data was already there.** v14's Unicorn-based behavioral pipeline
captured real MMIO traces of every executed function. The output C
(`behavioral_<fn>__<image>.synth.c`) is mechanical but faithful:
it lists every MMIO read and write in order, with correct addresses
and values.

The bug was the text-based scorer, which assumed every good function
has function calls. Most truth lane functions are **leaf functions**
with only MMIO operations — they touch hardware, they don't call
other functions.

The strong verifier:
- Detects leaves by checking if the disasm has any named BL targets
- For leaves, requires real register/MMIO operations in the body
- For calling functions, requires at least one real callee matching
  a BL target
